================================================================================
2. WHAT THIS GAME IS
================================================================================

OVERDRIVE is a realistic-leaning 3D driving game that runs entirely in the
browser. It is built on the same codebase that previously contained the neon
arcade game NEON RUSH. The OVERDRIVE UI is the active application. The older
NEON RUSH modules still exist in src/game/ and are used by OVERDRIVE for:
  - src/game/particles.ts     — pooled GPU particle systems
  - src/game/credits.ts       — developer attribution
  - src/components/Icons.tsx  — shared SVG icon set

Do not confuse the two:
  - ACTIVE GAME:  src/overdrive/ + src/App.tsx + src/index.css
  - LEGACY CODE:  src/game/GameEngine.ts, track.ts, environment.ts, carModel.ts,
                  audio.ts, data.ts etc. (not referenced by the active app except
                  particles.ts and credits.ts). They can be removed later, but
                  verify imports first.

Core experience:
  - 11 real production cars with individual physics data.
  - 6 circuits / environments in India and international-inspired settings.
  - 4 modes: Circuit Race, Time Trial, Sprint, Drift Attack.
  - Automatic and manual gearboxes.
  - Dynamic weather and time of day.
  - Chase, wide chase, hood and right-hand-drive cockpit cameras.
  - 3D garage viewer and internal model studio.
  - Fully rebindable keyboard controls, touch controls, local saves.
  - No backend, login, online multiplayer, analytics or cloud storage.

================================================================================
9. ENGINE LIFECYCLE AND MAIN LOOP
================================================================================

Construction:
  new OverdriveGame(container, config, callbacks)
  callbacks: onHud(HudState), onFinish(RaceResult), onPause(), onReady()
  - create RoadTrack and add its group
  - create WorldRig (environment)
  - create procedural PMREM environment map
  - create player visual + 5 AI visuals (race/sprint only)
  - create particle pools
  - build post-processing composer (high quality only)
  - resize, attach listeners, start audio, requestAnimationFrame
  - expose window.__OVERDRIVE__ for debugging/QA

Main loop:
  requestAnimationFrame(loop)
  raw = (now - last)/1000
  if paused: update camera, render, return
  accumulator = min(0.5, accumulator + raw)
  while accumulator >= 1/60 and steps < 24:
      tick(1/60)
      accumulator -= 1/60
      steps++
  if steps === 0: updateCamera(raw)
  render()

render():
  composer.render() on high quality, else renderer.render()

tick(dt):
  - world.update (sun follows player, clouds, rain)
  - elapsed += dt while racing
  - countdown / racing / finished phase logic
  - updatePlayer, updateRivals, resolveCollisions
  - audio.updateEngine
  - visual wheel spin/steer, body roll/pitch/bob
  - particles, camera, HUD snapshot ~20 Hz

Phase:
  "countdown" 3.2 s; countdown numbers; audio beeps; throttle can be held.
  "racing" simulation runs, clock runs.
  "finished" player slows; results callback after 1.2 s.

Pause/resume/restart:
  pause() sets paused, clears keys, mutes engine, resets clock.
  resume() clears accumulator, unmutes.
  restart() resets player/rivals/phase/timers/audio but keeps scene.

Dispose:
  cancel RAF, clear finish timer, remove all listeners, disconnect observers,
  dispose geometries/materials/particles/composer/renderer, force context loss,
  remove canvas, clear scene. Always call when leaving the race.

Resize:
  resize() bound arrow, called by window resize, orientationchange,
  fullscreenchange and ResizeObserver. Canvas always matches container.
  Drawing buffer pixel ratio: high <=2, medium <=1.5, low 1.

HUD snapshot every ~0.05 s contains:
  speed km/h, rpm normalized, gear string/number, redline, fuel, damage,
  position, totalRacers, lap, totalLaps, time, lapTime, bestLap, countdown,
  drifting, driftAngle, driftScore, mode, weather, timeOfDay, carName,
  trackName, wrongWay, checkpoint/message, standings[], minimap[], camera,
  boosting (always false — no nitro system in OVERDRIVE), topSpeed, sector,
  traction, message.


================================================================================
10. DRIVING PHYSICS — EXACT MODEL (src/overdrive/engine.ts)
================================================================================

Units: metres, seconds, kilograms, radians. Forward is +Z at heading 0.

State (PlayerState):
  pos Vector3, vel Vector3 (world), heading (yaw), index (nearest road sample),
  progress 0..1, lap, lapStart, bestLap, sector bitmask, crossedLine,
  finished, finishTime, spin (wheel rotation accumulation), steering -1..1,
  gear (0 = reverse, 1..N), rpm, shifting timer, throttle 0..1, brake 0..1,
  handbrake, drifting, driftScore, driftTime, damage 0..100, fuel 0..100,
  topSpeed, wrongWay, wallCooldown, carCooldown, offRoad, headlights, traction.

Axes:
  forward = (sin(heading), 0, cos(heading))
  right   = (cos(heading), 0, -sin(heading))
  forwardSpeed = vel · forward
  lateralSpeed = vel · right

Input smoothing:
  throttle = damp(throttle, accelerate ? 1 : 0, 9, dt)
  brake    = damp(brake,    brakeKey ? 1 : 0, 12, dt)
  steerInput = (left ? 1 : 0) - (right ? 1 : 0)   (times min(1.25, sensitivity))
  steering  = damp(steering, steerInput, handbrake ? 11 : 7.5, dt)

Surface grip:
  baseGrip   = car.grip * surfaceGrip()
  surfaceGrip = SURFACE_GRIP[weather] * track.grip
  SURFACE_GRIP = clear 1.0, sunset 0.98, overcast 0.92, rain 0.76, night 0.9
  onRoad = !offRoad (offRoad when |lateral offset| > halfWidth - 1.0)
  surfaceMul = onRoad ? 1 : 0.58
  grip = baseGrip * surfaceMul * (handbrake ? 0.16 : 1) * (assists ? 1.06 : 1)

Reverse:
  From standstill with brake held and no throttle -> gear = 0.
  Reverse acceleration: -3.2 m/s² * brake (limited to -12 m/s).
  Forward motion with brake and no throttle exits reverse to gear 1.

Automatic gearbox:
  rpm = rpmForGear(gear, |forwardSpeed|)
  upshift when rpm > redline * 0.95, gear < count, throttle > 0.15,
    shifting timer <= 0 -> gear++, shifting = 0.18
  downshift when rpm < idle + 500, gear > 1 -> gear--, shifting = 0.16
  at standstill with brake and no throttle -> gear = 0 (reverse)

Manual gearbox:
  shift(±1) via keys (E/Q by default)
  blocked while shifting timer > 0 or in reverse
  blocked if upshifting would put rpm below idle + 200 while speed < 8 m/s
  sets shifting = 0.2 and updates rpm

RPM:
  wheelRps = speed / (2π * wheelRadius)
  rpmForGear = wheelRps * 60 * finalDrive * gearRatio
  At speed < 6 m/s with gear >= 1: rpm approximated from throttle.
  During shift: rpm forced to idle + 0.35 * (redline - idle).
  rpm damped toward target with lambda 9, clamped idle..redline.
  rpmNorm = (rpm - idle) / (redline - idle), clamped 0..1.

Torque and drive force:
  torqueCurve = 0.6 + 0.4 * sin(π * min(1, rpmNorm * 0.9 + 0.08))
  gearRatio = gears[gear-1] (3.2 in reverse)
  driveForce = torque * torqueCurve * gearRatio * finalDrive * 0.78 / wheelRadius
    (N; 0.78 is the overall drivetrain efficiency factor)

Longitudinal:
  engineFactor = fuel > 0.5 ? 1 : 0
  damageFactor = damage enabled ? 1 - min(0.35, damage * 0.0035) : 1
  axial += (driveForce / mass * throttle * engineFactor * damageFactor
            - brake * brakePower * 10.5) * dt     [gear >= 1]
  reverse branch subtracts brake * 2.2 * dt
  coasting: axial *= exp(-0.55 * dt) when no throttle/brake
  handbrake: axial *= exp(-0.45 * dt)
  topMs = topSpeed / 3.6
  dragK = driveForce * 0.82 / (mass * topMs²)
  axial -= dragK * axial * |axial| * dt        (aero drag, tuned to topMs)
  axial -= (0.18 + (onRoad ? 0 : 1.8)) * sign(axial) * dt   (rolling resistance)
  axial -= roadTangentY * 9.81 * 0.42 * dt     (slope gravity)
  axial = min(axial, topMs)
  (There is no nitro/boost system in OVERDRIVE; HudState.boosting is false.)

Steering/yaw:
  speedRatio    = clamp(|axial| / topMs, 0, 1)
  steerAuthority= clamp(|axial| / 5.5, 0, 1)      (no steering at standstill)
  yaw = steering
        * 1.32
        * car.handling
        * steerAuthority
        * (1 - speedRatio * 0.46)
        * (handbrake ? 1.38 : 1)
        * (gear < 1 ? -1 : 1)
        * (assists ? 0.94 : 1.02)                  [rad/s]

Momentum/drift model (critical):
  worldX = forward.x * axial + right.x * lateral
  worldZ = forward.z * axial + right.z * lateral
  heading += yaw * dt
  recompute forward/right from new heading
  newForward = world · forward
  newLateral = world · right
  newLateral *= exp(-grip * 0.82 * dt)            (tyre scrub)
  counter-steer if |newLateral| > 3.5 and steering != 0:
      heading += sign(newLateral) * -0.14 * |steering| * dt
      recompute forward/right and reproject world velocity
  assists: if |newLateral| > 3.5 and throttle > 0.2 -> newLateral *= 0.9
  traction = (newLateral / max(1, |newForward|)) * 100    (for HUD/drift angle)
  vel = forward * newForward + right * newLateral
  pos += vel * dt

Collisions and bounds:
  index = nearestIndex(pos, index)
  lateral offset from road centre measured against sample.side
  offRoad = |offset| > halfWidth - 1.0
  wallLimit = halfWidth + 1.25
  if |offset| > wallLimit:
      push back to wallLimit along inward normal
      impact = vel · outwardNormal
      if impact > 0: vel -= outwardNormal * impact * 1.22   (restitution 22%)
      vel *= 0.78
      sparks, camera shake and crash audio if impact > 2.2 and cooldown <= 0
      damage enabled: damage += |impact| * 0.9 (cap 100)
      messages at damage > 45 and > 75
  wallCooldown 0.45 s, carCooldown 0.5 s
  pos.y damped to road centre y + 0.02 (lambda 16)

Wheel rotation:
  spin += (newForward / wheelRadius) * dt
  visual setSpin(spin) sets wheel.spin.rotation.x = -spin
  (Do not change to Z. See Section 11.)

Fuel, damage and drift:
  fuel -= dt * (0.006 + throttle * 0.05 + rpmNorm * 0.03), min 0
  low fuel message below 12
  drifting = racing && |forward| > 9 && (|lateral slip| > 2.3 ||
             (handbrake && |forward| > 12))
  while drifting: driftScore += (|slip| * 12 + |forward| * 0.9) * dt,
                  slight fuel recharge
  otherwise driftScore decays 14/s
  damage shown only if config.damage

AI (updateRivals):
  5 rivals only in race and sprint; none in time trial/drift.
  Curvature look-ahead: max over 16 samples starting at
    lookSteps = round((12 + speed * 0.55) / 2.4)
  cornerLimit = (spec.topSpeed / 3.6) * (1 - clamp(curve * 290, 0, 0.52))
                * surfaceGrip()
  target = cornerLimit * skill * rubberBand
  rubberBand = 1 + clamp((playerScore - aiScore) * 0.09, -0.05, 0.09)
  accelerate at (torque / mass) * 2.4, brake at 14 m/s²
  lane sway via sin, steering eases toward a look-ahead point (max 1.6 rad/s)
  lap counting on wrapped index crossing (crossedStart guard)

Car-to-car:
  separation radius 2.4 m, push apart, transfer velocity, audio/shake/damage.

Camera:
  chase: distance 7.4 (portrait 9.6), height 2.25; far: 12 m / 3.4 m
  hood: +0.9 m forward, 1.15 m up, look 24 m ahead
  cockpit: per-car eye point from CAR_DESIGNS.cockpit via localPoint
  countdown orbit camera, paused orbit camera, lookBack inverts the shot
  camera clamped inside circuit width and above road
  FOV 58 + speedRatio * 8 + drift 2, damped
  Camera shake added on impacts.

Race rules:
  totalLaps = sprint ? 1 : drift ? 3 : track.laps
  Start grid: player at samples.length - 6; AI staggered behind.
  First start-line crossing (prev > 0.78 && current < 0.22) opens lap 1.
  A lap counts only if both sector gates (34% and 67%) were passed.
  Race finishes when lap >= totalLaps; finishRace builds standings and result.

11. WHEEL SYSTEM — INVARIANTS (DO NOT BREAK)
================================================================================

The wheel bug in earlier builds: the tyre axle was aligned to X, but the spin
group was rotated on Z, producing a sideways-spinning wheel. This was fixed.

Hierarchy (per wheel):
  root
   └── steer group      position = (side * track/2, wheelRadius,
                                    front ? +wheelbase/2 : -wheelbase/2)
        ├── spin group   rotation.x = -spinAngle
        │    ├── tyre mesh (CylinderGeometry rotated so axle = local X)
        │    ├── rim barrel, rim face, spokes, bolts, lip
        ├── brake disc   (child of steer, does NOT spin)
        └── brake caliper(child of steer, does NOT spin)

Rules:
  1. Four wheels, two front and two rear.
  2. Steering affects only front `steer.rotation.y`.
  3. Rear steer rotation.y stays 0.
  4. Rolling affects only `spin.rotation.x`.
  5. `spin.rotation.y` and `.z` must remain 0.
  6. Wheel centre height = design.wheelRadius (ground contact).
  7. Track width = design.track; wheels sit slightly outside the body.
  8. Wheels must remain children of the vehicle root; never reparented.
  9. Rolling rate = forward speed / wheelRadius (metres per second).
 10. Do not reintroduce the huge opaque arch liner that hid the tyre.
 11. Brake disc/caliper are unsprung; do not attach them to `spin`.
 12. Wheel styles and sizes come from CAR_DESIGNS; do not hard-code one size.

Debug API (window.__OVERDRIVE__):
  debugWheels() returns for each wheel:
    { front, side, steerY, spinX, contactY, radius, position[3] }
  contactY is world Y minus radius (world Y is track elevation, so use local
  positions for exact ground-contact checks; local steer.position.y equals
  radius by construction).

Verified assertions (headless, live gameplay):
  four wheels, all attached, 2 front/2 rear, local Y == radius,
  front axle at +wheelbase/2, rear at -wheelbase/2, track width consistent,
  front steers on Y, rear does not, spin on X only, no Z spin,
  spin changes with speed, zero console errors.

Garage viewer:
  VehicleViewer uses its own renderer and studio scene. It shows the live
  procedural model, turntable ring, shadows and four preset angles. Pointer
  drag orbits, wheel zooms. It reads CAR_DESIGNS and carModel; keep them
  compatible with any future geometry changes.

Model studio:
  Open `<live-url>#models`. Lists all cars, quality presets, angle controls,
  dimensions. Use it to inspect every model before and after changes.

12. VEHICLE GEOMETRY — HOW IT IS BUILT
================================================================================

Body:
  - `design.top` is a list of [z, y] points from nose to tail.
  - A THREE.SplineCurve smooths them into ~85 points.
  - A THREE.Shape is built from the top profile plus the bottom (lowerY) and
    the cut-outs for both wheel arches. `fromRearToFront` inserts the arch arcs
    in ascending z order so the shape remains valid.
  - ExtrudeGeometry with bevel (segments 3, small bevel) gives a round-edged
    body; rotated -90° about Y and centred so X is width, Z is length.
  - bodyDepth = width * 0.93; track = width + 0.06 means the wheels protrude
    slightly, so the arches read properly.

Cabin:
  - Separate extruded shape from cabin.frontZ/rearZ, roofFrontZ/roofRearZ and
    roofY, with cabin.width, bevel and curved front/rear.
  - Painted in body colour.

Glazing:
  - Side panes from `design.glassFront` / `glassRear` polygons, placed just
    outside the cabin shell; a dark backing panel ensures the window reads as
    glass even against dark scenery.
  - Windscreen and rear screen are quad meshes between beltline and roof.
  - Window surrounds are Line segments; pillars are added for blacked-out cars.

Details:
  - Grille textures generated on canvas per grille type.
  - Kidney grille gets two rounded openings with chrome slats.
  - Headlights: swept/slim/LED/round variants, DRL strip, LED cubes for SUV.
  - Taillights: swept/slim/round/quad; separate brake, reverse, indicator.
  - Front/rear bumpers, splitter, diffuser, exhausts (twin/quad), wing, lip.
  - Mirrors with glass inserts, door handles, shut lines, chrome trim option,
    roof rails, side steps, spare wheel, hood scoop/vents, side intakes,
    antenna.
  - Right-hand-drive interior: dash, cluster, steering wheel, seats, console,
    shifter, mirror, A-pillars. Interior visible only in cockpit camera.

Reference mapping:
  Swift   : red hatchback, compact, black roof/pillars, mesh grille, swept lamps.
  City    : silver sedan, chrome bar grille, slim lamps, multi-spoke wheels.
  Fortuner: white large SUV, tall roof, roof rails, side steps, chrome slats,
            LED headlights, off-road-style tyres/clearance.
  M3      : green performance sedan, kidney grille, quad exhaust, splitter,
            diffuser, carbon roof, wide track.
  F296    : red mid-engine supercar, low roof, centre-lock wheels, mesh grille,
            quad taillights, diffuser, side intakes, twin exhaust.

Honest limitation:
  These are procedural interpretations, not licensed CAD or photo-scanned
  replicas. They are distinct and recognisable by class and features, but they
  will not match the reference renders pixel-for-pixel. Authoring proper GLB
  meshes (Blender) and loading each through GLTFLoader is the correct next step
  for photorealism. The per-car design pipeline is ready for that replacement.

14. TRACKS — src/overdrive/data.ts + track.ts
================================================================================

TrackDef fields:
  id, name, location, theme ("circuit"|"coast"|"hill"|"city"), description,
  rx, rz (horizontal radii), harmonicA, harmonicB (shape variation),
  elevation, width, laps, lengthLabel, difficulty, weather, timeOfDay, grip,
  accent, skyTop, skyHorizon, fog, terrain.

Roster:
  ng-speedway   Greater Noida Speedway    circuit  3 laps  width 15  dry/day
  kari-circuit  Kari Motor Speedway       circuit  4 laps  width 12  dry/day
  ecr-coast     East Coast Road Sprint     coast    2 laps  width 13.5 sunset
  munnar-climb  Munnar Hillclimb          hill     2 laps  width 10.5 elevation 52
  lonavala-ghat Lonavala Ghat Loop        hill     2 laps  width 11  rain
  mumbai-street Mumbai City Sprint        city     3 laps  width 12  night

Generation:
  - 48 control points around a closed loop:
      radius = 1 + harmonicA*sin(3a+0.7) + harmonicB*cos(5a+1.9)
               + 0.45*harmonicB*sin(8a+0.2)
      x = cos(a)*rx*radius
      z = sin(a)*rz*radius
      y = 2 + elevation*(0.5+0.5*sin(2a+0.5))*(theme==="hill" ? 1 : 0.5)
  - CatmullRomCurve3 closed, tension 0.4.
  - Samples: count = clamp(length/2.4, 380, 1400).
  - curvature = angle between tangents 4 samples apart / arc span.
  - nearestIndex uses ±60 sample local search when a hint is given.
  - sampleAt(progress) interpolates positions/tangents/sides.
  - minimap points normalised to 0..1.
  - Road width, kerbs, barriers, arches, start gantry and checkpoints generated
    at 34% and 67%.
  - track.setWet(true) darkens/reflects asphalt, shows puddles, changes kerb and
    shoulder colour.

To add a track:
  1. Add TrackDef to TRACKS in data.ts and TrackId to types.ts.
  2. Optionally add theme-specific scenery in environment.ts.
  3. Verify width vs car widths, checkpoint spacing, elevation smoothness,
     camera containment and AI stability.
  4. Test all modes on it and record best-lap save.

Important note:
  Track names reference real places, but layouts are original procedural
  interpretations. Do not claim surveyed or officially licensed reproductions.

15. ENVIRONMENT, WEATHER, DAY/NIGHT, AUDIO
================================================================================

Environment (environment.ts):
  - Sky: custom ShaderMaterial sphere; uniforms for top/horizon/sun colour,
    night flag and sun direction. Sun disk and haze computed in shader.
  - Stars at night, cloud sprites, distant mountain cones, ground plane with
    terrain texture, instanced vegetation (trunks + crowns), rocks, palms on
    the coast, sea/beach on coast.
  - City blocks with emissive window textures (night), instanced buildings.
  - Streetlights with emissive heads and point lights at night (limited count).
  - Tyre stacks and grandstands for circuits, pit wall, road signs, braking
    boards.
  - Rain: 3,500 pooled points that follow the player, with reset above ground.
  - Fog colour/intensity per track and weather.
  - Sun follows the player so shadows remain local and stable.
  - Quality controls vegetation count, city density, shadow map size and whether
    shadow casting is enabled (low = no shadows).
  - createWorld returns { group, sun, update(focus, elapsed, dt), setRain, dispose }.

Weather/time:
  Weather values: clear, overcast, rain, sunset, night.
  TimeOfDay: day, sunset, night.
  Race config resolves "track" to the circuit default. Night weather forces
  night time; sunset weather forces sunset.
  Rain sets the track wet, adds rain particles and reduces grip.
  Lights: player headlights toggle (L) and are auto-on at night; AI lights are
  emissive only (spotlights only for the player to limit light count).

Audio (audio.ts):
  - One AudioContext per page (singleton via getDriveAudio()).
  - Created/resumed on a user gesture (priming happens from App actions).
  - Buses: master -> destination; music, sfx, engine -> master.
  - Engine: 3 oscillators through a lowpass filter plus a sine sub and noise
    layers for road/wind/rain/tyre squeal.
  - updateEngine params: rpm, redline, throttle, speed, gear, shifting,
    drifting, rain, surfaceGrip, engineLoad.
  - Gear up triggers a shift pop; near redline triggers a limiter blip.
  - SFX: countdown, UI click/confirm/back, checkpoint, lap, shift indicator,
    crash, finish sting.
  - Music: generated four-chord progression loop, not a licensed track.
  - Settings master/music/sfx applied via setSettings.
  - dispose() closes the context; engine mute is used when paused/exiting.
  - Known limitation: engine note is parameterised by RPM/gear but not by a
    per-car sample or cylinder count. Extending: add per-car timbre data and
    vary oscillator types/harmonics/filter curves.

Particles (src/game/particles.ts):
  ParticlePool(max, additive) with shader-based points, fixed buffers.
  Engine uses 3 pools: smoke (220), spray (320), sparks (160).
  Emission: drifting/handbrake, wet spray at speed, off-road dust, wall sparks.
  Call update(dt) each frame; dispose on exit.

  - Model studio: all 11 cars render; reference cars captured from front, side,
    rear and 3/4 in screenshots/models/.

What was NOT validated end-to-end:
  - Full multi-lap races with the automated harness (software rendering made the
    session too slow). Sprint was validated end-to-end instead. A real browser
    playtest of a 3-lap race is recommended.
  - Real-GPU frame rate and thermal performance.
  - Actual GitHub Actions deployment (no repo/credentials in this environment).
    The build was served from a simulated repository subpath and tested.
  - Safari/Firefox compatibility; only Chromium was available.
  - The racing-line setting has no visual implementation yet (UI only).
  - Fuel cannot be refilled in-session; low-fuel warning only.
  - Car damage is numeric and affects power; no visual deformation or panel
    damage is implemented.
  - No cockpit-specific interior per car; the interior structure is shared with
    different belt/roof heights.
  - Vehicle geometry accuracy is stylised/procedural, not photo-exact.

19. KNOWN ISSUES / BUGS
================================================================================

1. Vehicle models are recognisable procedural interpretations, not exact
   replicas of the reference renders. Highest-priority visual gap.
2. The "Show racing line" setting is present but not applied to the road.
   Either implement it or remove the toggle to avoid a fake setting.
3. Full race distances are not covered by automated end-to-end tests.
4. Fuel has no refill mechanism; long sessions run dry.
5. `HudState.boosting` always false (no nitro system). Remove the field or
   implement a real system before displaying boost UI.
6. The legacy NEON RUSH modules still exist in src/game/ and increase the
   repository size/confusion. They can be pruned after checking imports.
7. No save export/import or multi-profile support.
8. No online multiplayer, career, dealership, economy or achievements. Do not
   present UI for these unless implemented.
9. AI difficulty is not user-selectable.
10. The fullscreen API must be triggered by a user gesture; the settings button
    does so. Browser support varies.
11. Headless software WebGL produces lower-fidelity screenshots than a real GPU;
    appearance of bloom/wet reflections may differ.
12. External Google Fonts may be blocked; fallback fonts are used.
13. The black wheel-arch liner was removed because it occluded the wheel. If
    adding a new liner, keep it behind the tyre and smaller than the arch.
14. Steering in the cockpit: front wheels visually turn up to ~24° through
    `steer.rotation.y`; verify after changing handling or wheel geometry.
15. The archive of screenshots includes some pre-rebuild models under
    screenshots/models/*.png (v1/front/side) and newer *-v2.png. Use the v2 files
    as current reference for the rebuilt geometry.
